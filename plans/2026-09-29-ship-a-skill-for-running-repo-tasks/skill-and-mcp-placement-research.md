# Where tools ship agent skills and MCP servers — research, 2026-09-28/29

Three research passes, run as subagents from a repo-tasks session. Sources are local clones under
`$RESEARCH_HOME/repos/` unless a URL or "gh API" is named. Percentages from marketplaces and the MCP
registry are heuristic (repo-name classification plus spot checks), and marketplace figures reflect
each clone's ref, not today's upstream.

## 1. Skills: in the tool's repo or a dedicated one

### Census

anthropics/claude-plugins-official `.claude-plugin/marketplace.json` (clone 2026-09-25), 314
entries: 52 hosted in Anthropic's repo, 262 external. Of the external ones:

- dedicated AI/skills/plugin repo: 227 (87%) — cloudflare/skills, stripe/ai, vercel/vercel-plugin,
  huggingface/skills, expo/skills, mongodb/agent-skills, awslabs/agent-plugins,
  getsentry/plugin-claude, prisma/claude-plugin, supabase-community/supabase-plugin
- the vendor's MCP-server repo: 13 (5%) — atlassian-mcp-server, chrome-devtools-mcp, exa-mcp-server,
  zapier-mcp
- the vendor's product code repo: 17 plugins in 15 repos (6.5%) — getsentry/cli,
  mergifyio/mergify-cli, JetBrains/teamcity-cli, CodSpeedHQ/codspeed, confident-ai/deepeval,
  heygen-com/hyperframes, ServiceNow/sdk, SAP/open-ux-tools, spotify/save-to-spotify,
  oracle/netsuite-suitecloud-sdk
- a samples repo: 5 (2%)

CLI-shaped tools skew to the product repo; platform/service vendors skew to dedicated repos.

claude-plugins-community, 2,282 entries: 55% in repos whose name marks them as skills/plugins, 119
with "mcp" in the name. A 60-entry random sample of the remaining 908 found about 23% were tool
repos shipping their own plugin; extrapolated, roughly 9% of all entries. Unverified per entry.

github/awesome-copilot `plugins/external.json`, 68 entries: about 6 in product repos (Microsoft
WinAppCli, Build-CLI, rayfin; Azure Connectors, git-ape; fastrepl/anarlog), 2 in MCP repos, about 60
dedicated (dotnet/skills, elastic/agent-skills, stripe/ai).

### How the skills CLI finds a skill inside a code repo (vercel-labs/skills, clone 2026-09-17)

- `src/skills.ts:253-260`: searches the repo root, `skills/`,
  `skills/.curated|.experimental|.system`, and about 30 agent directories (`.agents/skills`,
  `.claude/skills`, `.github/skills`, …; L12-40). Walks container directories up to 3 levels
  (L262-308), falls back to a recursive search or `--full-depth` (L310). `SKIP_DIRS` excludes
  node_modules, dist, build (L10).
- Also reads skill paths from `.claude-plugin/marketplace.json` or `plugin.json`
  (`src/plugin-manifest.ts:77-106`).
- Subpaths: `/tree/<ref>/<path>` URLs and `owner/repo/path` shorthand
  (`src/source-parser.ts:412-547`).
- Refs: `#ref` and `#ref@skill` (L284-314), undocumented in the README; Prisma's docs use
  `skills#v<version>`. The lock records `ref` "for ref-aware updates" and `skillFolderHash`
  (`src/skill-lock.ts:21,29`).
- Package-bundled skills: `experimental_sync` scans `node_modules` only (`src/sync.ts:44-51`).
- The agentskills spec says nothing about distribution or versioning with a tool; `version` appears
  only as an example under `metadata` (`docs/specification.mdx:53,159`).

Counter-examples: Cloudflare, Supabase, Stripe, Neon, Hugging Face use dedicated repos and their
skills cover a platform, not one CLI; Supabase's and Stripe's CLI repos have no `skills/`. Astral's
uv and ruff ship no user-facing skill.

### Stated reasons

- Prisma (`skills/README.md`, gh API): "`prisma-8` ships inside the … tarballs, so the skill in your
  project always describes the version you installed"; "versioned with the rest of Prisma 8 … so
  there is no separate skill-version axis". Installing from GitHub is "interoperability, not the
  recommended path: nothing keeps a copy installed this way up to date."
- gog (`docs/agent-skills.md:9-11,41`): "generated from `gog schema --json`, so their command lists
  stay aligned with the installed CLI … commit the resulting service-skill changes together."
- JetBrains, for going separate (github.com/JetBrains/teamcity-cli/pull/401): the in-repo skill
  "drifted from the copies used by other TeamCity AI surfaces"; now "one source of truth [for] every
  surface", and "`go.sum` pins the content, so builds are reproducible".
- Firecrawl (`README.md:86`): CLI skills authored in the CLI repo, SDK skills in the product
  monorepo, aggregated into a read-only catalog.

## 2. MCP servers: built into the tool or separate

### Census

claude-plugins-official, 314 plugins: 171 declare an MCP server. About 113 (66%) use a hosted URL.
Of the 58 that launch something locally:

- the vendor's separate MCP package or repo: 33 (13 Google `@toolbox-sdk/server`, 6 AWS
  `awslabs.*-mcp-server`, plus `@playwright/mcp`, `@pinecone-database/mcp`, `@azure/mcp`,
  hashicorp/terraform-mcp-server, grafana/mcp-grafana, and others)
- built into the product's own CLI or package: 7 — `npx firebase-tools mcp`, `npx prisma mcp`,
  `npx convex mcp start`, `uvx browser-use --cli-mcp`, `hana-cli-mcp`, `semgrep mcp`,
  `php artisan boost:mcp`
- the product is itself an MCP server: 4; a local proxy to a hosted server: about 7; other: about 7

Of the 15 product repos in that marketplace, 12 ship skills only, with no MCP. The CLI-product repos
(Sentry, TeamCity, Mergify, save-to-spotify) all ship a skill that teaches calling the CLI.

claude-plugins-community, random sample of 400: 102 declare MCP, 44 hosted only, 23 ship their own
script inside the plugin, 3 run a product-CLI subcommand.

MCP registry, 37,075 latest entries (live API, `registry.modelcontextprotocol.io/v0/servers`): 49%
in repos named for MCP, 24% in repos not so named, 22% hosted only, 3% in a subfolder of a non-MCP
repo. 830 entries (5% of those with a package) run a non-MCP-named package with an `mcp`/`serve`/
`stdio` argument — the built-in subcommand pattern (`snyk mcp`, `@gitkraken/gk mcp`,
`@appfigures/cli mcp`, firebase-tools `src/mcp`).

### Built-in modes, confirmed in clones

mise `mise mcp`; Backlog.md `backlog mcp`; gogcli `gog mcp`; flyctl `fly mcp server`; Heroku
`heroku mcp:start` (spawns the separately published `@heroku/mcp-server` it bundles); firebase-tools
`firebase mcp`; marimo `edit --mcp`; repomix `--mcp`; claude-task-master's second executable
`task-master-mcp`; goose `goose mcp <name>`. Via code search only: Angular `ng mcp`, Semgrep,
GitButler `but mcp`, moon, kubectl-ai, Snyk.

Separate package in the same repo: beads `integrations/beads-mcp`, version kept in lockstep by
`scripts/check-versions.sh:47`; SAP fiori-mcp-server. The `microsoft/playwright-mcp` repo is a thin
wrapper; its source is in the Playwright monorepo.

Separate repo: ast-grep-mcp (Python, "experimental", calls the `ast-grep` binary; no stated
rationale), docker `mcp-gateway`, github-mcp-server, terraform-mcp-server, sentry-mcp, supabase-mcp,
grafana, trivy-mcp.

No MCP: deno, gh, uv, bun, ollama (clones); ruff, Stripe CLI, Pulumi (code search).

Reversals: semgrep went separate to built in — the archived `semgrep/mcp` README says it "has been
moved from a standalone repo to the main semgrep repository… further updates… via the official
semgrep binary". googleworkspace/cli added `gws mcp` and later removed it with no stated reason, and
now ships `skills/` and a `gemini-extension.json` instead.

### Stated reasons

- beads (`integrations/beads-mcp/README.md:6-8`): "For environments with shell access… the CLI +
  hooks approach is recommended over MCP. It uses ~1-2k tokens vs 10-50k for MCP schemas… Use this
  MCP server for MCP-only environments like Claude Desktop."
- playwright-cli (`README.md:9-11`): "coding agents increasingly favor CLI–based workflows exposed
  as SKILLs over MCP because CLI invocations are more token-efficient… MCP remains relevant for…
  persistent state… long-running autonomous workflows."

## 3. Tying a skill's version to the installed tool

### Mechanisms

- vercel-labs/skills `experimental_sync` — shipped, experimental. Scans top-level `node_modules/*`
  and `@scope/*` for a root `SKILL.md`, `skills/*/SKILL.md` or `.agents/skills/*/SKILL.md`, copies
  into agent dirs, records `sourceType: 'node_modules'` and a `computedHash` in `skills-lock.json`
  (`src/sync.ts:44-132,190-223,392`). No npm source type in `source-parser.ts`; git refs via
  `owner/repo#ref` (L285-311).
- vercel-labs/skills #2323, opened 2026-09-28 — proposal to graduate it into `skills sync`: a
  `package.json` `"skills": [...]` field, `npm:<pkg>` entries, `version` and `via` in the lock.
  "When the library updates, the skill does not… The skill version always matches the installed
  package version." Related: PR #937 (open since 2026-04-15), versioning RFC #11 (open since
  2026-01). gh API.
- antfu/skills-npm — shipped, v4.0.0. `skills-npm setup` hooks the `prepare` script so skills are
  re-linked on every `npm install`; its README names the problem: "Version mismatch – Skills and
  tools update separately".
- TanStack Intent (`@tanstack/intent`) — shipped, 0.4.0. Packages opt in with the npm keyword
  `tanstack-intent` and ship `skills/`; frontmatter carries `metadata.library_version`.
  `intent install` writes a marker-fenced pointer into AGENTS.md; `intent load pkg#skill` prints the
  installed version's SKILL.md; `intent stale` reports drift, with a CI template. 422 packages carry
  the keyword (npm registry search), among them `@reduxjs/toolkit`, `@apollo/client`,
  `@trpc/server`.
- Claude Code plugins from an npm source — shipped: version pinning (changelog 2.1.51), update
  detection fixed (2.1.128), `npm pack --ignore-scripts` with integrity checks (2.1.275). No PyPI
  source.
- `gh skill install owner/repo skill@version` / `--pin` — shipped. Without a version it takes the
  latest tagged release, else HEAD (`pkg/cmd/skills/install/install.go:134-191`).
- Specs: agentskills defines no distribution or versioning. agent-plugins-spec 1.1.0 has a plugin
  `version` for update checks, explicitly rejects "registry-fetched bundles", and lists dependency
  constraints under future considerations.
- Python: no tool found that scans `site-packages` the way these scan `node_modules`. A web search
  surfaced `pyskills`, unverified.

### Tools that install their own guidance

- beads `bd setup <recipe>` (Go): writes `.agents/skills/beads/SKILL.md` from `go:embed`, a
  versioned, hashed `<!-- BEGIN BEADS INTEGRATION v:1 … -->` block into AGENTS.md/CLAUDE.md, and a
  `SessionStart` hook running `bd prime`. `--check` reports "installed but stale" against the
  embedded template.
- Backlog.md `backlog init`: writes a small nudge block with `backlog.md-instructions-version`,
  replaced in place on rerun. The nudge only says to run `backlog instructions overview`, which the
  installed binary prints — so it always matches the tool version.
- spec-kit `specify init` (Python, uv tool): bundles templates in the wheel via hatch
  `force-include`; `specify integration upgrade` uses a manifest and refuses to overwrite a locally
  edited file without `--force`. Its docs: "The CLI tool is separate from your project files".
- comfy-cli `comfy skills install|status|uninstall|show` (Python): reads bundled SKILL.md through
  `importlib.resources`; a sha256 manifest reports `current`, `stale`, `modified`, `missing`,
  `unmanaged`.
- graphify `graphify install` (PyPI `graphifyy`): copies the skill with a `.graphify_version` stamp
  and warns on mismatch.
- google-colab-cli `colab skill`: prints the bundled SKILL.md.
- dstack: `skills/` at the repo root for `npx skills add`, and the same files force-included into
  the wheel.
- task-master: copies a bundled AGENTS.md and appends an `@` import to CLAUDE.md; refreshed only on
  rerun.

### Drift seen in practice

- graphify #1568: the skill-version warning recommends `graphify install` even when the skill is
  newer than the package, a silent downgrade — the code comment calls this "common for a stale
  `uv tool` CLI". https://github.com/Graphify-Labs/graphify/issues/1568
- graphify #3144: one install path never wrote the stamp, so the warning became permanent, "and
  install silently overwrites a modified SKILL.md".
- beads #2493: generated AGENTS.md "still refers to bd sync command" after its removal.
  https://github.com/gastownhall/beads/issues/2493
- beads #5710, #2902: templates missing a newer knob; two init commands writing conflicting
  AGENTS.md guidance.

### Patterns

1. Copy, plus a stamp or hash, plus a check command — beads, comfy-cli, graphify, spec-kit. Each
   grew staleness detection; graphify also needed downgrade protection.
2. A thin pointer, plus the tool printing its own guidance — Backlog.md, Intent `load`, `bd prime`,
   `colab skill`. Cannot drift by construction.
3. Git-tag pinning (`gh skill …@vX`, `npx skills add owner/repo#vX`) is the only way to version a
   separate-repo install, and neither ties it to what uv installed.
